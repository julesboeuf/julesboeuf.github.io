  Migration vers une base de données NoSQL  

Ce projet s’inscrit dans le cadre d’un module visant à l’apprentissage des principes et de l’exploitation des bases de données orientées Big Data. L’objectif était de partir d’une base de données relationnelle pour la convertir en une base de données MongoDB. Il a alors fallu s’approprier les données en analysant le schéma de la base de données d’origine, ainsi que son contenu.

À la différence d’une base de données traditionnelle, les base de données comme MongoDB (orientée document) stockent leur donnée sous forme de collections de documents. Les données sont enregistrées sous le format JSON, qui permet de conserver un format structuré et faciliter la jointure de documents. Pour transitionner vers une base de données MongoDB, une phase de réflexion était nécessaire afin de réfléchir au nombre de collections nécessaires ainsi que le format des fichiers JSON. La base de données utilisée pour ce projet contenait des informations concernant la gestion du covid-19 dans différents pays. Chaque table concernait un aspect différent de la gestion de cette crise : vaccinations, nombre d’hospitalisation, de décès… Etc. Ainsi que des statistiques relatives aux pays : nombre d’habitant, continent, PIB par exemple. Le choix de la structure de la base de données MongoDB s’est alors porté sur deux collections, une servant à stocker les informations économiques/géographiques/sociales des pays, l’autre contenant les statistiques liées au covid à l’échelle journalière pour chaque pays. Dans ce schéma, la clé commune entre les deux collections était le nom du pays.

La migration s’est déroulée en langage Python, grâce à la librairie Pymongo permettant de se connecter et gérer localement l’outil MongoDB. Les données ont d’abord été nettoyées, car des dates devaient être corrigées, et des indicateurs statistiques ont été réalisés. Pour effectuer la transformation, des requêtes SQL ont été préparées pour obtenir les données dans un DataFrame. Ensuite, elles ont été traitées de telle sorte qu’elles correspondent au format désiré pour la collection de la nouvelle base de données.

Pour valider la migration, 13 requêtes de tests ont été réalisées. Cette validation repose sur la comparaison des résultats de deux requêtes similaires : une requête SQL exécutée sur la base de données d’origine, et une requête Pymongo exécutée sur la nouvelle base de données. Les résultats obtenus étaient identiques, ce qui a confirmé le bon fonctionnement de la migration. Un tableau de bord a ensuite été mis en place pour mettre en valeurs les données.

Compétences acquises :

  • Utilisation, stockage, exploitation et création d’une base de données NoSQL orientée document
  • Création de requête Pymongo
  • Approfondissement des langages Python et SQL
  • Compréhension des enjeux liés à la transition vers le Big Data
